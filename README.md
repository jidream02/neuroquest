# NeuroQuest

Кроссплатформенное мобильное приложение (Android / iOS / Web) на **React Native + Expo**:
настольная ролевая игра в духе D&D, где роль **Мастера Подземелий играет ИИ**.

Игрок создаёт героя (раса, класс, характеристики), выбирает мир и пишет действия героя.
ИИ-мастер рассказывает историю, а когда исход действия неочевиден, просит **бросить d20**.
Сам бросок, урон, лечение, опыт, уровни и инвентарь **считает код приложения по правилам**, а не ИИ.

## Проблема, которую решает приложение

Для настольной ролевой игры нужен ведущий (мастер), который готовит сюжет и знает правила.
Собрать компанию и найти мастера сложно. NeuroQuest позволяет играть в любое время в одиночку:
ИИ ведёт сюжет, а приложение следит за правилами и хранит прогресс.

## Запуск

Нужно: Node.js (рекомендуется ≥ 22.13; на 20.19 работает с предупреждением), npm.

```bash
# 1. Установка
npm install
npm --prefix server install

# 2. Сервер ИИ-мастера (держит ключ Gemini)
cp server/.env.example server/.env   # вписать GEMINI_API_KEY (бесплатно: aistudio.google.com)
npm run server                       # http://localhost:8787

# 3. Приложение (во втором терминале)
npm run web        # в браузере: http://localhost:8081
npm start          # QR-код для Expo Go (телефон в той же Wi-Fi сети) / клавиши a, i для эмуляторов
```

Без ключа сервер работает в режиме **офлайн-мастера** (сценарное приключение «Башня на холме»).
Если недоступен сам сервер, тот же офлайн-мастер встроен в приложение: игра работает даже без сети,
а его реплики помечены «офлайн».

### APK для Android

```bash
npx eas-cli login                                        # один раз, аккаунт expo.dev
npx eas-cli build -p android --profile preview           # облачная сборка → ссылка на .apk
```

В установленном APK адрес сервера задаётся в «Профиль → Свой адрес сервера»
(например `http://192.168.1.10:8787`, телефон и ПК в одной Wi-Fi сети).
Для работы с сервером по локальной сети в сборке разрешён HTTP (`usesCleartextTraffic`).
Это компромисс для демо: в релизе сервер должен работать по HTTPS.
Телефон и эмулятор находят сервер автоматически по IP компьютера, на котором запущен Expo.
Адрес можно задать и вручную: `EXPO_PUBLIC_API_URL=http://192.168.1.10:8787`.

Проверки:

```bash
npm test             # unit-тесты (крипто, правила, валидация, бэкап, протокол ИИ)
npm run typecheck    # TypeScript
npx expo lint        # ESLint
```

### База данных (SQLite)

`users` → `characters` → `items`; `users` → `campaigns` → `messages`; `audit_log`.
Внешние ключи с `ON DELETE CASCADE`, `CHECK`-ограничения (HP ≥ 0, уровень 1–20…),
миграции по `PRAGMA user_version`. Данные сохраняются после перезапуска (на Web — в хранилище браузера).

## Информационная безопасность

| Требование | Реализация | Где |
|---|---|---|
| Пароли не в открытом виде | PBKDF2-HMAC-SHA256, 60 000 итераций, соль 16 байт, сравнение за постоянное время | `src/lib/crypto.ts` |
| Защита от перебора | 5 ошибок → блокировка 30 с, дальше ×2 до 15 мин (хранится в БД) | `src/services/auth.ts` |
| Нет утечки «существует ли логин» | одинаковое сообщение, фиктивная проверка хэша | `auth.ts` |
| Безопасное хранение | сессия в SecureStore (Keychain / Android Keystore); Android `allowBackup: false` | `secureStorage.ts`, `app.json` |
| Контроль доступа | каждый SQL-запрос ограничен `user_id`; защищённые маршруты `Stack.Protected` | `src/db/repo.ts`, `src/app/_layout.tsx` |
| Сессии | истекают через 30 мин; автоблокировка через 2 мин в фоне | `AuthContext.tsx` |
| SQL-инъекции | только параметризованные запросы `?` | `repo.ts` |
| Валидация ввода | схемы zod на каждой форме, очистка невидимых и управляющих символов, лимиты длины | `src/lib/validation.ts` |
| Ответы ИИ не доверенные | схема ответа + ограничение эффектов кодом (HP, XP, предметы) | `shared/dmProtocol.ts`, `rules.ts` |
| Prompt injection | действие игрока помечено как данные, правило в системном промпте | `server/src/prompt.ts` |
| Секретные ключи | ключ Gemini только на сервере в `.env` (в `.gitignore`), в приложении его нет | `server/` |
| Защита сервера | rate limit 20/мин, лимит тела 64 КБ, CORS, заголовки безопасности, без стек-трейсов | `server/src/index.ts` |
| Ошибки | понятные сообщения, повтор хода, единый обработчик на сервере | везде |
| Аудит | журнал входов, ошибок, бэкапов | `audit_log`, экран «Безопасность» |

## Резервное копирование и восстановление

* **Backup**: данные пользователя → JSON → SHA-256 → **AES-256-GCM** (ключ из пароля копии через PBKDF2) → файл `.nqbak`.
  Сразу после создания копия расшифровывается и сверяется (проверка корректности).
  Android/iOS: файл в папке приложения, кнопка «Поделиться». Web: файл скачивается.
* **Restore**: проверка формата → расшифровка (неверный пароль или изменённый файл отклоняются тегом GCM) →
  контрольная сумма → схема и ссылки между таблицами → замена данных **одной транзакцией** →
  сверка количества записей (если не совпало, откат).
